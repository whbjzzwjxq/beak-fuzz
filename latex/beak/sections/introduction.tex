\section{Introduction}\label{sec:intro}

Zero-knowledge virtual machines (zkVMs) enable a prover to execute arbitrary RISC-V programs and produce succinct cryptographic proofs of correct execution~\cite{risc0, sp1, jolt}. Production deployments already underpin blockchain scaling solutions, privacy-preserving applications, and off-chain computation platforms securing billions of dollars in digital assets~\cite{openvm, nexus, pico}. The security of these deployments hinges on a critical invariant: the zkVM's arithmetization---the polynomial constraints encoding the execution trace---must faithfully capture the RISC-V instruction semantics. When this alignment fails, a malicious prover can forge proofs for incorrect executions, undermining the entire trust model.

Detecting such \emph{semantic gaps} is extremely challenging. The constraint systems are large (hundreds of thousands of constraints), component interactions are subtle (e.g., the ALU must agree with the memory subsystem on the value written to a register), and bugs manifest only under specific \emph{boundary conditions}: rare combinations of operand values, instruction orderings, and execution states that exercise edge cases in the arithmetization. These bugs rarely surface during normal testing or standard security audits.

Existing approaches fall short. Static analysis tools such as \zkap~\cite{zkap} detect generic patterns (e.g., unconstrained signals) but lack zkVM-specific semantic structure. Symbolic approaches such as Picus~\cite{picus} encode witness uniqueness as SMT queries, but are limited to the Circom ecosystem where circuits are orders of magnitude smaller; the nonlinear arithmetic over 254-bit prime fields and cross-table dependencies in zkVM arithmetizations place them beyond current solver capacity. Dynamic approaches such as \arguzz~\cite{arguzz} combine metamorphic testing with fault injection, but rely on generic mutation strategies unlikely to reach the boundary conditions where constraint bugs hide; in our experiments, \arguzz times out on the majority of benchmarks. All three lack a \emph{semantic model} of what constitutes a boundary condition and---crucially---how that model can simultaneously steer exploration \emph{and} localize detection.

Our key insight is that soundness-critical gaps in zkVMs arise at \emph{semantic boundary conditions} that become observable when heterogeneous backend traces are \emph{lifted into a common semantic space}. Although each zkVM represents its execution trace differently, the constraint-correctness concerns they share---immediate value decomposition, memory address alignment, control flow target binding, arithmetic overflow handling, and the $2^n$-sized algebraic data structures mandated by STARK arithmetization---can be captured by a small, well-defined set of semantic categories. By naming these categories and using them as a \emph{dual-use} signal---simultaneously a coverage metric for exploration and a targeting cue for detection---a fuzzer can systematically explore the semantic dimensions where bugs cluster, and then immediately probe each activated boundary for constraint soundness. This unifies divergence discovery (Type~I) and underconstraint detection (Type~II) in a single feedback-driven loop.

Based on this insight, we introduce \tool, a semantics-guided differential fuzzing framework for discovering constraint bugs in RISC-V zkVMs. \tool makes two core contributions. First, it defines a \emph{cross-zkVM semantic model} that unifies six heterogeneous zkVM backends (OpenVM, SP1, RISC Zero, Jolt, Nexus, and Pico) into a common space of \tbd{39} semantic categories: \tbd{32} derived empirically from audit reports and prior dynamic testing, and \tbd{7} derived structurally from the $2^n$ algebraic sizing constraints of STARK trace tables, segments, memory/bytecode regions, lookup accumulators, commitment vectors, and range-check tables (\autoref{sec:trace-ir}). Second, it builds a closed-loop \emph{boundary-driven fuzzing framework} on this shared abstraction: category signature novelty replaces edge coverage as the feedback signal, a UCB1 multi-armed bandit governs \tbd{8} ISA-aware mutation strategies, and \emph{every} category activation doubles as an anchor for targeted semantic witness injection. The same categories that score exploration also identify which constraint window to probe and what kind of witness perturbation to apply, turning blind $\sim$$10^8$-step injection into a focused $\sim$$64$-trial probe (\autoref{sec:fuzzing-framework}).

We evaluate \tool on all six backends against a ground-truth benchmark of \tbd{44} known vulnerabilities sourced from zero-day discovery, prior dynamic testing, security audits, and public issue trackers. \tool detects \tbd{34 of 44} bugs (\tbd{77.3\% recall}). On the four backends where Arguzz~\cite{arguzz} has full support, \tool detects \tbd{17} bugs to Arguzz's \tbd{11} (\tbd{$1.5\times$}); across all six backends---including two for which Arguzz lacks backend adapters---\tool detects \tbd{34} vs.\ \tbd{11}. \tool additionally discovers \tbd{6} previously unknown zero-day vulnerabilities, including \tbd{4} critical soundness bugs allowing forging proofs for incorrect RISC-V execution. All zero-day vulnerabilities have been responsibly disclosed to the respective development teams.

In summary, we contribute:
\begin{itemize}
    \item A \textbf{cross-zkVM semantic model} of \tbd{39} semantic categories (\tbd{32} empirical + \tbd{7} structural, derived from the $2^n$ algebraic structure of STARK arithmetization) that unifies six backends (\autoref{sec:trace-ir}).
    \item A \textbf{unified boundary-driven fuzzing loop} in which category signatures serve a dual role---driving bandit-guided ISA-aware mutation \emph{and} targeting semantic witness injection---so exploration and detection share the same coverage signal (\autoref{sec:fuzzing-framework}).
    \item A \textbf{comprehensive evaluation} achieving \tbd{77.3\%} recall on \tbd{44} known bugs (\tbd{$1.5\times$} over the state-of-the-art on comparable backends) and \tbd{6} zero-day discoveries (\autoref{sec:eval}). We will open-source \tool upon acceptance.
\end{itemize}
